## 한 일

### 1. CatBoost 하이퍼파라미터 튜닝 반영 — 리더보드 875 → 889점
- `work/tune_catboost.py` 신규 작성: CatBoost `learning_rate`/`depth`/`l2_leaf_reg`/`bagging_temperature`/`random_strength`/`border_count`를 무작위로 조합해 15 trial + baseline 비교. 실행 중 세션이 끊겨 baseline + trial 0~6까지만 완료된 상태로 중단됐다가, `random.Random(SEED)` 고정 특성을 이용해 이미 나온 결과는 캐시로 재사용하고 trial 7~14만 이어서 실행해 재개.
- 최고 결과: trial 7 (learning_rate=0.01, depth=8, l2_leaf_reg=20, bagging_temperature=1, random_strength=1, border_count=32) — auc=0.55056, baseline(0.55005) 대비 +0.0005로 로컬 개선폭은 작았음.
- `train_catboost.py`에 해당 파라미터를 `BEST_PARAMS`로 반영해 재학습(검증 auc=0.55056, best_iteration=1053), `model_catboost/catboost.cbm` 및 `submit_catboost/model/catboost.cbm` 갱신.
- `work/submit_v4_catboost.zip` 재생성(클린룸 스모크 테스트 통과) 후 제출 → **리더보드 875 → 889점 (+14)**. 이번에도 로컬 AUC 개선폭(+0.0005)보다 리더보드 상승폭이 상대적으로 크게 나타남(CatBoost 최초 채택 때와 유사한 패턴).
- **현재 최선 버전: `submit_v4_catboost.zip` (889점).** `submit_v3_catboost.zip`(875점)은 참고용으로 유지.

### 2. 실험: raw id 재도입 / 블렌딩 정밀화 / 저카디널리티 교차 피처 — 전부 기각, v4로 원복
- **raw id 재도입** (`work/tune_catboost_rawid.py`): CatBoost의 ordered target statistics가 LightGBM과 달리 고카디널리티 `pitcher_id`/`batter_id`를 과적합 없이 다룰 수 있을지 테스트. 결과 auc=0.54712로 현재 채택 버전(0.55056) 대비 **-0.00344**, best_iteration도 104회에서 조기종료(현재 버전은 1053회) — CatBoost도 이 카디널리티(792/830개)에선 과적합 못 피함. **기각.**
- **블렌드 가중치 정밀 탐색** (`work/tune_blend.py`): 기존 50/50 고정 블렌드(tune_v2.py) 대신 LightGBM 5시드 배깅 + CatBoost 예측을 0.02 간격으로 가중치 스윕. 최적 지점(catboost 74%)에서 auc=0.55070, CatBoost 단독 대비 **+0.00015**로 노이즈 수준. 제출용 패키지에 모델 2개를 유지해야 하는 복잡도 대비 이득이 없어 **기각.**
- **저카디널리티 trackman 교차 피처 3종** (`work/tune_cross2.py`): 5키 풀교차(181조합, 이전 실패)와 달리 `hand_outs`(pitcher_hand×batter_hand×outs_before, 12조합), `count_light`(balls×strikes, 12조합), `hand_inning_half`(pitcher_hand×batter_hand×top_bottom, 8조합) 세 개를 개별 테스트 → 셋 다 baseline보다 근소하게 좋음(+0.00004~+0.00010), 3종 결합 시 auc=0.55083(+0.00027)으로 로컬 검증에서는 가장 유의미해 보이는 결과.
  - `build_trackman_context.py`에 정식 반영하고 재학습(`model_catboost/catboost.cbm` 갱신, 피처 69→93개) → `work/submit_v5_catboost.zip` 제출.
  - **리더보드 결과: 889 → 880점 (-9), 로컬은 올랐는데 리더보드는 내려감.** 지난번 파라미터 튜닝(로컬 +0.0005 → 리더보드 +14, 같은 방향·비슷한 스케일)과 비교하면 방향 자체가 반대로 나온 이례적인 케이스.
  - 원인으로 추정: `tune_cross2.py`가 "2024 검증셋 기준으로 baseline보다 나은 후보만" 골라 조합하는 선택 편향(selection bias) 구조였고, 개별 후보 개선폭(+0.00004~+0.00010)이 애초에 단일 홀드아웃 분할의 노이즈 수준이라 2024 홀드아웃에만 우연히 맞았던 패턴으로 보임. raw id 제거(+0.0112)나 CatBoost 전환(+0.0012)처럼 로컬·리더보드가 같은 방향으로 크게 움직였던 진짜 신호들과는 스케일 자체가 다름.
  - **기각.** `build_trackman_context.py`/`model_catboost/`/`submit_catboost/model/`을 커밋된 v4 상태로 git checkout 원복, `submit_v5_catboost.zip` 및 관련 로그 삭제. 실험 스크립트 3종(`tune_blend.py`, `tune_catboost_rawid.py`, `tune_cross2.py`)은 참고용으로 보존.
