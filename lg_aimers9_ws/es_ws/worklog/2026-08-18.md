### 2. 앙상블+확률보정 검증 — 핵심은 앙상블이 아니라 "확률보정" 단독 효과, 실제 지표(BSS)에서 큰 폭 개선
- `tune_ensemble_calibrated.py` 신규 작성: jh_ws v9와 동일하게 CatBoost+LightGBM+XGBoost 3모델을 각각 `CalibratedClassifierCV(sigmoid)`로 보정 후 Optuna 3-way 블렌드. es_ws 피처셋(trackman context 포함, raw id 제외)·동일 시간분할(2019~2023 학습/2024 검증)로 재현.
- **1차 실행(AUC 기준)**: 보정 전후 AUC가 완전히 동일(catboost 0.55056→0.55056, lgb/xgb도 마찬가지). **이유**: sigmoid 보정은 확률의 순서를 안 바꾸는 monotonic 변환이라 AUC(순위 지표)엔 원천적으로 안 잡힘. 대회 실제 채점 지표는 AUC가 아니라 BSS(Brier Skill Score, 확률 제곱오차 기반, jh_ws train.py의 `bss_score` 함수와 동일 — 로컬 BSS 738.0/800대 스케일이 실제 리더보드 점수(738→924 등)와 같은 스케일)라는 걸 재확인하고 BSS로 재측정.
- **2차 실행(BSS 기준)**: 2024 홀드아웃에서 baseline(CatBoost 단일, 보정없음) BSS=800.75 → 3모델 블렌드+보정 BSS=**827.73 (+26.98)**. 분해해보면 이득의 대부분(+24.8)이 "CatBoost 하나에 보정만 추가"에서 나오고, LGBM/XGBoost를 앙상블로 더하는 건 겨우 +2.2 추가 — **핵심 신호는 앙상블이 아니라 확률보정 자체**. 실제로 raw(비보정) 예측 3개로 Optuna 블렌드를 최적화시키면 CatBoost에 99.97% 가중치를 몰아줌(비보정 상태에선 다른 두 모델이 사실상 무가치, tune_blend.py 8/16 결과와 일치).
- 이 스케일(800.75→827.73, +3.4%)은 지금까지 봤던 다른 후보들(±0.0003~0.0005, 노이즈 경계)과 질적으로 다름 — jh_ws의 v9(CV 방식 전환, 909→924) 급 임팩트일 가능성.

### 3. 프로덕션 파이프라인에 확률보정 반영 — `submit_v6_catboost_calibrated` 패키징
- 사용자 승인 하에 CatBoost 단독 + 확률보정만 프로덕션에 반영(앙상블 3모델은 이득의 대부분을 차지하지 않아 복잡도 대비 이득이 적다고 판단, 보정만 우선 적용).

- `pipeline/train_catboost.py` 수정: (1) 2024 홀드아웃에서 raw/calibrated BSS 둘 다 계산해 검증 재확인(raw 800.75 → calibrated 825.57, +24.81 — jh_ws 피처와 다른 es_ws 자체 피처셋에서도 같은 크기로 재현됨), (2) 최종 전체데이터 재학습 시 jh_ws train_final.py와 동일한 방식으로 5% stratified carve-out을 떼어내 여기에 Platt scaling을 fit(전체 데이터로 학습한 모델을 그 데이터로 다시 보정하면 리키지이므로, 학습에서 제외된 홀드아웃에 보정을 fit해야 함). carve-out(랜덤 5%, iid) 기준 BSS는 raw 1948.56→calibrated 1960.06(+11.5)로 2024 시간분할 홀드아웃(+24.8)보다 상대적으로 작게 나옴 — carve-out이 iid라 원래 덜 miscalibrated된 것으로 보이며, 실제 2025 예측은 시간적 분포이동이 있는 상황이라 2024 홀드아웃 수치(+24.8)가 더 대표성 있을 가능성.
- `feature_meta.json`에 `"calibration": {"method": "platt_sigmoid", "a": ..., "b": ...}` 필드 추가.
- `submissions/submit_v6_catboost_calibrated/` 패키징(`script.py`가 추론 시 raw 확률에 Platt scaling 적용) 후 클린룸 2회 검증(스테이징 폴더 실행 + zip 재추출 후 재실행, 예측값 동일) 통과. `submit_v6_catboost_calibrated.zip` 생성 완료.

### 6. 다음 세션 후보 (미착수, 우선순위 순)
오늘 통한 두 개(확률보정 +70, raw id +15)의 공통점: 둘 다 "AUC엔 안 잡히지만 BSS엔 잡히는" 유형의 신호였다. 이 관찰을 기준으로 다음 후보를 우선순위화.

1. **Isotonic 보정으로 교체** (우선순위 최상) — 지금 쓰는 Platt/sigmoid는 2-파라미터 직선 변환이라 표현력이 제한적. 실제로 carve-out(iid)에서 raw→calibrated 격차가 시간분할 홀드아웃보다 더 크게 나온 걸 보면(섹션3 참고) 아직 못 잡은 비선형 미보정이 남아있을 가능성. Isotonic은 비모수라 더 유연하지만 계단함수라 작은 홀드아웃에 과적합하기 쉬우므로, 지금 5%인 calibration carve-out을 좀 더 키우거나 홀드아웃 크기 민감도를 먼저 확인해야 함. jh_ws의 `isotonic_blend`(8/17)가 이미 시도했지만 그때는 랜덤 K-Fold+unseen ID 문제가 섞여있어 isotonic 자체 효과가 검증된 적 없음 — 오늘의 정제된(시간분할+raw id 포함) 파이프라인 위에서 재시도할 가치 있음.
2. **2023년 데이터 레짐 변화를 명시적 피처로** (우선순위 중) — 지금까지 "2023 폴드가 이상하다"(game_type F/R의 control_success 관계 역전, 8/17 기록)를 노이즈로 취급하고 우회만 해왔는데, 어쩌면 진짜 신호일 수 있음. `season>=2023` 여부와 `game_type`의 교차 피처, 혹은 시즌별 game_type 분포 자체를 인코딩하는 방안을 시도해볼 만함. 다만 test.csv가 2025시즌이라 "2023부터 시작된 변화가 2025에도 이어지는지"는 불확실 — 검증 시 2024 단일 폴드가 아니라 2023+2024 두 폴드 모두에서 방향이 일관되는지 봐야 함.
3. **jh_ws 방식 상관계수/importance 피처 필터링 도입** (우선순위 낮음) — es_ws엔 없는 단계. 지금까지 패턴상 피처 개수 조정 자체는 효과가 작았던 축(팀 이력, cross feature 등 대부분 기각)이라 우선순위 낮게 봄.
4. **raw id를 CatBoost 자체 hash/embedding 대신 빈도/최근성 기반 파생피처로 보완** (우선순위 낮음, 탐색적) — 792/830개 카디널리티에서 label-encoding만으로 +9.48을 얻었으니, "이 투수가 등장한 총 횟수"나 "최근 등장 간격" 같은 파생값을 추가하면 추가 이득이 있을지 궁금하지만 근거는 약함.
