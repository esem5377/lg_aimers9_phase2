## 한 일

### 1. 데이터 구조 파악
- `open/data_description.md` 및 `open/data/*.csv` 확인.
- 파일 구성: `train.csv`(2019~2024, 1,475,092행×49컬럼), `test.csv`(형식 확인용 5행 샘플, 실제 평가는 2025시즌 비공개 데이터로 서버에서 교체), `sample_submission.csv`, `trackman_history.csv`(2019~2024 투구 실측 로그, 1,793,078행×30컬럼, **미사용**).
- EDA 결과
  - 타깃 분포: `control_success=1` 52.4% / `0` 47.6% (불균형 크지 않음)
  - 시즌별 행 수 균등 (연 24~25만행)
  - 결측치는 대부분 0%대, `asof_*` 이력 피처만 최대 ~2% (콜드스타트 케이스)
  - `pitcher_id` 792명, `batter_id` 830명, 팀 ID 각 13개

### 2. 환경 세팅
- `python3 -m venv`가 sudo 없이 불완전(`python3-venv` 패키지 필요)해서 `pip3 install --user --break-system-packages`로 pandas/scikit-learn/lightgbm/joblib 설치.
- 설치 버전: pandas 3.0.5, scikit-learn 1.9.0, lightgbm 4.7.0, joblib 1.5.3 (주최측 baseline 예시의 `scikit-learn==1.8.0` 등과 버전 다름 — 평가 서버가 `requirements.txt` 기준으로 재설치 가능한 환경인지는 미확인).

### 3. 베이스라인 모델 학습
- `work/train.py`: LightGBM 분류기 학습.
  - 범주형 9개(`top_bottom`, `game_type`, `base_state`, `pitcher_hand`, `batter_hand`, `pitcher_id`, `batter_id`, `pitcher_team_id`, `batter_team_id`)는 category dtype으로 네이티브 처리, 결측치도 LightGBM이 자체 처리.
  - **검증은 랜덤 분할 대신 시간 기반 홀드아웃 사용**: 2019~2023 학습 / 2024 검증. 실제 평가가 2025시즌(미래 시점)이라 랜덤 분할보다 실전 성능을 더 잘 대변한다고 판단.
  - 검증 결과: AUC 0.534 / logloss 0.692 / accuracy@0.5 0.526 — 랜덤(0.5)보다 소폭 나은 수준.
  - feature importance 상위: `batter_id`, `pitcher_id`가 압도적 — 원시 ID 기반 암묵적 평균 학습으로 보이나 개선폭이 크지 않아, 이 태스크 자체의 신호가 원래 약할 가능성.
  - best_iteration 기준으로 전체 데이터(2019~2024) 재학습 후 `work/model/lgbm.pkl` 저장.

### 4. 추론 스크립트 및 제출 패키징
- `work/predict.py`: 로컬 검증용 추론 스크립트. `feature_meta.pkl`에 학습 시 카테고리 목록을 저장해, 추론 시 test에만 있는 미지 범주값은 NaN 처리(`cat.set_categories` 사용, deprecation 경고 회피).
- `work/submit/script.py`: `open/baseline_submit/script.py`와 동일한 인터페이스(`./data`, `./model`, `./output` 경로 규칙)로 작성.
- `open/baseline_submit`(주최측 예시: `script.py` + `model/rf.pkl` + `requirements.txt`)와 zip 루트 구조를 동일하게 맞춰 `work/first_submit.zip` 생성.
- `open/data`를 심볼릭 링크해 end-to-end 실행 검증 완료 (`output/submission.csv`가 `sample_submission.csv`와 동일 포맷으로 정상 생성).

### 5. 제출 및 결과
- `first_submit.zip` 리더보드 제출 → **채점 결과 400점**.
- 팀원 기존 모델은 900점 수준이라고 전달받음. 로컬 검증 AUC(0.534, 거의 랜덤)가 점수에 그대로 반영된 것으로 보임.

### 6. 기타 논의
- 학습 리소스 관련 질문에 답변: 이 태스크(148만행 규모 GBDT 학습) 기준으로는 RAM/CPU가 병목이 아니었음(30GB RAM, 16코어면 충분, 학습 1~2분). GPU는 불필요. 코어 수는 학습 "속도"에만 영향, 결과 점수와는 무관 — 400 vs 900 격차는 리소스가 아니라 피처 엔지니어링/모델링 방식 차이일 가능성이 크다고 판단.
